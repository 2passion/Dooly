# 최종 로드맵

현재 단계는 여기까지입니다.

```text
Level 1
조교 챗봇
(현재 목표)

↓

Level 2
조교 관리 시스템
(업무지시/보고/추적)

↓

Level 3
KingMath OS
(학원 전체 운영)
```

따라서 구현 계획서는 아래 순서가 가장 효율적입니다.

```text
1. SOP 작성
2. 예외상황 매뉴얼 작성
3. 조교 질문 사례집 작성
4. 표준 매뉴얼 v1.0 작성
5. Assistant OS 설계
6. Claude+Obsidian+GitHub 구조 구축
7. 조교 챗봇 개발
8. 조교 관리 시스템 개발
9. KingMath OS 확장
```

이 순서대로 가면 현재 대화 내용의 중복을 약 70~80% 줄이면서, 실제 개발에 필요한 문서 체계만 남길 수 있습니다.

### 1. 조교 교육

* 업무 매뉴얼 설명

### 2. 업무 지시 관리

* 원장 지시사항 등록
* 담당 조교 배정
* 업무 상태 관리

### 3. 업무 보고 관리

* 완료 보고 접수
* 진행 상황 기록
* 미완료 업무 추적

### 4. 매뉴얼 관리

* SOP 검색
* 예외상황 FAQ 안내
* 변경사항 공지

### 5. 운영 로그 관리

* 업무 이력 기록

* 인수인계 지원

담당자 : A조교

```text

변경 전 : 5권
변경 후 : 3권

변경사항이 모든 조교 공지사항에 반영되었습니다.

Phase 1

업무 관리

- 질문 입력

----------------

Phase 4

운영 로그

----------------

Phase 5

GitHub 자동 백업
```

---

현재 상태를 평가하면:

```text
프로젝트 비전      100%
프로젝트 범위      100%
역할 정의          100%
문서 체계          95%
화면 구조          85%
DB 구조            90%

구현계획서          0%
Claude Code 설계    0%
실제 개발           0%
```

따라서 다음 단계는 더 이상 구조 논의가 아니라,

**"01_King_Assistant_OS_v1.0_구현계획서.md"**

를 작성하여 Claude Code가 바로 개발을 시작할 수 있는 수준으로 구체화하는 것입니다. 그 문서에는 다음이 포함되어야 합니다.

1. 화면 목록(UI 구조)
2. DB 스키마
3. 폴더 구조
4. 기능 명세서
5. 개발 단계(Phase 1~5)
6. Claude Code 작업지시서
7. GitHub 운영 규칙
8. SESSION_HANDOVER 규칙

이제 사실상 설계 단계는 마무리되고, 구현계획서 작성 단계로 넘어갈 준비가 된 상태입니다.
