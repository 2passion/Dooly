현재 사용자의 SMART, CheckFlow, PrintFlow, 조교관리 시스템까지 고려하면 
앞으로는 프로젝트마다 반드시 아래 두 파일을 유지하는 것을 추천합니다.
PROJECT_MASTER.md
SESSION_HANDOVER.md
실제로는 이 두 파일만 잘 관리해도 Claude Code 채팅창이 
10만 토큰이 넘어가서 새 채팅을 열어도 90% 이상 원래 맥락을 복구할 수 있습니다.
특히 SESSION_HANDOVER.md를 
"현재 상태 → 진행 중 → 다음 작업 → 주의사항" 형식으로 강제하면, 
새 채팅창을 열 때마다 긴 대화 내용을 복사할 필요가 없어지고 
Claude Code + GitHub + Obsidian 조합이 사실상 
지속 가능한 개발 시스템으로 동작하게 됩니다.

├─ 진행 상황 추적

├─ 복테 관리
├─ 오답노트 관리
├─ 비품 관리
├─ 로그 관리
└─ GitHub 백업
같은 학원 운영 체계 전체입니다.



실제로는
Level 1
조교 챗봇
↓
Level 2
조교 관리 시스템
↓
Level 3
학원 운영 시스템 (KingMath OS)
이라고 볼 수 있습니다.
현재까지 정리하신 자료를 보면 이미 "조교 업무 매뉴얼" 수준을 넘어섰고,
사람이 바뀌어도 업무가 유지되고
신규 조교 교육이 표준화되고
업무 변경사항이 기록되고
Claude Code와 GitHub로 버전 관리까지 되는
작은 기업의 운영 시스템 수준에 가깝습니다.


앞으로는 폴더 이름도 단순히 Assistant 보다는
KingMath-OS
또는
KingMath-Operating-System
으로 관리하면 프로젝트 목적이 훨씬 명확해질 것 같습니다.
